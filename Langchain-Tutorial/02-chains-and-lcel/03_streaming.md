# Streaming — Deep Dive Notes

## Why Streaming Matters

Without streaming: User waits 3-5 seconds staring at a blank screen, then gets the full response.

With streaming: First token appears in ~200ms, response builds word by word. **Perceived latency drops from seconds to milliseconds.**

---

## Streaming Types in LangChain

| Method | What It Yields | Use Case |
|--------|---------------|----------|
| `.stream()` | Output chunks | CLI, simple apps |
| `.astream()` | Output chunks (async) | Web servers |
| `.astream_events()` | All internal events | Advanced: know what each step is doing |
| `.astream_log()` | Detailed logs | Debugging |

---

## How Streaming Works Under the Hood

```
[Prompt]  → does NOT stream (instant formatting)
    ↓
[LLM]    → STREAMS tokens as they're generated by the model
    ↓
[Parser] → passes through chunks (StrOutputParser) OR buffers (PydanticParser)
    ↓
Your Code → receives chunks one at a time
```

The LLM is the streaming source. Everything else either passes through or buffers.

---

## .stream() — Synchronous Streaming

```python
chain = prompt | llm | StrOutputParser()

# Each chunk is a small piece of text (usually 1-3 tokens)
for chunk in chain.stream({"topic": "AI"}):
    print(chunk, end="", flush=True)
    # chunk = "Art"
    # chunk = "ificial"
    # chunk = " Int"
    # chunk = "elligence"
    # chunk = " is"
    # ...
```

### Key points:
- `flush=True` ensures immediate display (not buffered by print)
- Chunks are **not** word-aligned — they're token-aligned
- First chunk arrives after ~200-500ms (model warmup)
- Subsequent chunks arrive every ~20-50ms

---

## .astream() — Async Streaming

```python
async for chunk in chain.astream({"topic": "AI"}):
    print(chunk, end="", flush=True)
```

Use async when:
- Inside FastAPI/Starlette endpoints
- Running multiple streams concurrently
- Non-blocking I/O is needed

## .astream_events() — Event-Level Streaming

See **everything** happening inside the chain:

```python
async for event in chain.astream_events({"topic": "AI"}, version="v2"):
    print(event["event"], event.get("name"))
```

### Event Types

| Event | When It Fires | Data |
|-------|--------------|------|
| `on_chain_start` | Chain begins | Input |
| `on_chain_end` | Chain completes | Output |
| `on_chat_model_start` | LLM call begins | Messages |
| `on_chat_model_stream` | Each token from LLM | AIMessageChunk |
| `on_chat_model_end` | LLM call completes | Full AIMessage |
| `on_parser_start` | Parser begins | - |
| `on_parser_end` | Parser completes | Parsed output |
| `on_tool_start` | Tool execution begins | Tool input |
| `on_tool_end` | Tool execution completes | Tool output |

### Practical: Build a progress indicator
```python
async for event in chain.astream_events(input, version="v2"):
    if event["event"] == "on_chain_start":
        print("⏳ Processing...")
    elif event["event"] == "on_chat_model_stream":
        print(event["data"]["chunk"].content, end="")
    elif event["event"] == "on_chain_end":
        print("\n✅ Done!")
```

## Streaming in Web Apps (FastAPI + SSE)

### Server-Sent Events (SSE) Pattern
```python
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
import json

app = FastAPI()

@app.post("/chat/stream")
async def chat_stream(request: ChatRequest):
    async def event_generator():
        async for chunk in chain.astream({"input": request.message}):
            # SSE format
            yield f"data: {json.dumps({'token': chunk})}\n\n"
        yield f"data: {json.dumps({'event': 'done'})}\n\n"
    
    return StreamingResponse(
        event_generator(),
        media_type="text/event-stream"
    )
```

### WebSocket Pattern
```python
@app.websocket("/chat/ws")
async def websocket_chat(websocket: WebSocket):
    await websocket.accept()
    message = await websocket.receive_text()
    
    async for chunk in chain.astream({"input": message}):
        await websocket.send_text(chunk)
    
    await websocket.close()
```

## Which Parsers Support Streaming?

| Parser | Streaming? | Behavior |
|--------|-----------|----------|
| `StrOutputParser` | ✅ Yes | Passes each chunk through |
| `JsonOutputParser` | ✅ Yes | Yields partial JSON objects |
| `PydanticOutputParser` | ❌ No | Buffers until complete, then parses |
| `.with_structured_output()` | ✅ Yes | Yields partial Pydantic objects |
| `CommaSeparatedListOutputParser` | ❌ No | Buffers |

### Streaming JSON (partial objects)
```python
json_chain = prompt | llm | JsonOutputParser()

async for partial in json_chain.astream({"input": "..."}):
    print(partial)
    # {"name": "Al"}
    # {"name": "Alice", "age": 2}
    # {"name": "Alice", "age": 25}
    # {"name": "Alice", "age": 25, "city": "Mu"}
    # {"name": "Alice", "age": 25, "city": "Mumbai"}
```

## Custom Streaming Transformers

Transform chunks as they flow through:

### Generator function (sync)
```python
def add_prefix(chunks):
    yield "🤖 "  # Prefix before first chunk
    for chunk in chunks:
        yield chunk

chain = prompt | llm | StrOutputParser() | add_prefix
```

### Async generator
```python
async def token_counter(chunks):
    count = 0
    async for chunk in chunks:
        count += 1
        yield chunk
    yield f"\n[{count} chunks received]"
```

### Filter chunks
```python
def filter_empty(chunks):
    for chunk in chunks:
        if chunk.strip():  # Skip empty chunks
            yield chunk
```

## Stream vs Invoke — Performance Comparison

| Metric | .invoke() | .stream() |
|--------|-----------|-----------|
| Time to first byte | 2-5 seconds | 200-500ms |
| Total time | Same | Same |
| Memory (short response) | Same | Same |
| Memory (long response) | Holds full string | Processes chunks |
| User experience | Waiting → wall of text | Gradual, natural |

**Rule:** Always stream in user-facing apps. Use `.invoke()` for background/batch processing.

---

## Streaming Best Practices

1. **Always stream for UX** — users perceive streaming as 10x faster
2. **Use `flush=True`** — or output buffers hide your streaming
3. **Handle connection drops** — client may disconnect mid-stream
4. **Set timeouts** — don't stream forever if model hangs
5. **Use `astream_events` for multi-step chains** — know which step you're in
6. **Buffer for parsers that don't stream** — collect all chunks, then parse
7. **Send metadata events** — start/end/error events help frontend UX
8. **Test with slow connections** — streaming matters most on slow networks

## Common Gotcha

```python
# ❌ This DOESN'T stream — .invoke() waits for completion
result = chain.invoke(input)
print(result)  # Appears all at once

# ✅ This streams
for chunk in chain.stream(input):
    print(chunk, end="")  # Appears progressively
```

If you're using `.invoke()` anywhere in a streaming pipeline, you've broken the stream at that point.
